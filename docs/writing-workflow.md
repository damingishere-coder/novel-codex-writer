# 完整写作工作流

Novel Codex Writer 将每一章拆成可检查、可回退、可追踪的步骤。作者负责方向和最终确认，Codex 负责按规则准备资料、执行脚本和维护结构化记录。

## 总体原则

- 每次只操作当前活动小说。
- 写正文前必须存在已确认的章节细纲。
- 最近正文用于保持语气和衔接，current 用于保持长期状态。
- 正文、Markdown 记忆和作者最新修改是事实源。
- 索引可以删除并重建，不应成为唯一事实来源。
- AI 审查先报告问题，再由作者决定是否修改。

## 一章的标准流程

### 1. 确认当前小说

先读取：

```text
小说项目/projects.json
```

获取 `activeProjectId`，后续只能读取和写入：

```text
小说项目/作品/<activeProjectId>/
```

如果没有活动小说，应停止而不是猜测。

### 2. 读取写作规范

根据本章任务读取必要的文风、章节审查和题材规则。不要一次性加载全部参考资料。

写作规范的作用是提供方向，而不是把每章写成同一个模板。

### 3. 确认章节细纲

章节细纲格式：

```text
大纲/细纲_第XXX章.md
```

建议至少包含：

- 本章目标
- 关键情节点
- 冲突或压力
- 角色需要做出的选择
- 必须承接的前文
- 可推进的伏笔
- 字数与节奏预算
- 章末变化或钩子

如果细纲不存在，Agent 应先生成供作者确认，不能直接虚构正文。

### 4. 运行写作前诊断

示例：

```powershell
python .agents\skills\webnovel-writer\scripts\memory_doctor.py --chapter 1
```

先处理 error 和 workflow blocker。诊断失败时，不应继续写正文。

### 5. 生成写作任务书

示例：

```powershell
python .agents\skills\webnovel-writer\scripts\build_context.py --chapter 1 --budget-chars 1500
```

输出：

```text
记忆库/current/本章写作任务书.md
```

任务书应列出：

- 当前章节目标
- 必须全文读取的前置正文
- 当前人物和关系状态
- 相关伏笔、地点和设定
- 明确需要回查的来源

### 6. 读取最近正文

后续章节通常需要读取连续前五章的最新正式正文；不足五章时读取已有全部前章。

不得使用旧摘要、备份文件或 `.trash` 代替磁盘上的最新正文。

最近正文和 current 的职责不同：

- 最近正文：语言、节奏、场景衔接和细节。
- current：仍然有效的人物、关系、资源、伏笔和时间状态。

两者冲突时，应报告冲突，并优先尊重作者最新保存的正文。

### 7. 创作正文

按照细纲和任务书创作，但正文中不能泄漏创作工程词，例如：

- 本章
- 细纲
- 伏笔安排
- 读者爽点
- 作者计划

正文应像故事，而不是创作报告。

### 8. 运行确定性检查

示例：

```powershell
python .agents\skills\webnovel-writer\scripts\check_chapter.py --chapter 1
```

检查内容可包括：

- 章节号和文件名
- 正文字数
- 明显工程词泄漏
- 重复段落
- 标点和格式问题
- 常见 AI 套路表达

脚本检查只能覆盖可确定问题，不能代替文学判断。

### 9. 生成审查报告

审查采用 S1-S4 严重度：

| 级别 | 含义 | 处理 |
| --- | --- | --- |
| S1 | 硬性失败 | 必须修复后才能保存 |
| S2 | 明显冲突或严重质量问题 | 必须修改 |
| S3 | 节奏、AI 腔、爽点等建议 | 作者判断 |
| S4 | 标点和局部润色 | 可选 |

每条问题应包含：证据、影响和修法方向，不应只给空泛评价。

### 10. 作者确认与保存

AI 可以提出修改，也可以在草稿中应用建议，但正式正文必须由作者确认后保存。

推荐保存格式：

```text
正文/第XXX章_标题.md
审查报告/第XXX章_审查报告.md
```

### 11. 生成章节提交

章节提交不是 Git commit，而是一份面向后续创作的结构化记录。

建议包含：

- 一句话摘要
- 剧情推进
- 人物状态变化
- 关系变化
- 伏笔新增、推进或兑现
- 新增设定和不可违背事实
- 章末状态与下一章钩子

### 12. 生成 memory patch

memory patch 只记录会影响后续创作的变化，不复制整章正文。

常见操作：

- `upsert`：新增或更新仍有效的事实
- `close`：结束任务、伏笔或临时状态
- `archive`：将被替换的旧状态移入档案

先执行 dry-run：

```powershell
python .agents\skills\webnovel-writer\scripts\update_memory.py --patch <补丁文件> --dry-run
```

确认无错误后再正式应用。

### 13. 更新 current、索引与档案

应用补丁后：

- 下一章仍有效的状态进入 current。
- 已结束或被替换的内容进入档案。
- 索引重新构建或更新。
- 已应用 patch ID 被记录，避免重复执行。

同一个 patch ID 重复执行应安全跳过；相同 ID 但内容不同应报错。

## 篇章结束后的压缩

snapshot 用于完整篇章结束后的阶段总结，不建议机械地每几章生成一次。

示例：

```powershell
python .agents\skills\webnovel-writer\scripts\compact_memory.py --range 001-030 --dry-run
```

确认范围和结果后，再去掉 `--dry-run`。

压缩不会删除正式正文。它的目的只是降低后续检索负担。

## 推荐的 Codex 提示词

### 初始化作品

```text
请使用 webnovel-writer Skill，读取当前小说的大纲/原始大纲.md。
先不要写正文，请整理总纲、篇纲和章节规划，并初始化 current 投影与索引。
```

### 写下一章

```text
请使用 webnovel-writer Skill，继续写第 12 章。
先运行写作前诊断，确认章节细纲，生成写作任务书，并全文读取任务书列出的连续前置正文。
完成正文后运行章节检查，生成审查报告；修复 S1、S2 后保存正式正文，再生成章节提交和 memory patch，先 dry-run 后更新记忆。
```

### 只审查不改写

```text
请使用 webnovel-writer Skill 审查第 12 章。
只输出带具体证据的 S1-S4 报告，不要大段重写正文，也不要改变作者已有的人物口吻。
```

## 不应做的事

- 默认读取整部小说全部正文。
- 跨小说补充人物或设定。
- 在作者未确认细纲时直接生成正式章节。
- 用摘要替代最近正式正文。
- 把 current 无限追加成流水账。
- 未 dry-run 就批量修改长期记忆。
- 在作者未确认时自动覆盖正式正文。
