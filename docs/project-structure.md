# 项目目录与数据说明

本项目把“程序文件”和“小说事实数据”分开管理。理解这个边界，有助于备份、迁移和安全使用。

## 仓库主要部分

```text
webnovel-writer-Skill/
├── .agents/                    # Codex Skill、规则、参考资料和辅助脚本
├── docs/                       # 面向用户与贡献者的文档
├── 小说项目/                  # 作品库与每本小说的数据
├── README.md                   # 中文项目主页
├── README.en.md                # English project homepage
├── CONTRIBUTING.md             # 贡献指南
├── SECURITY.md                 # 安全说明
├── ROADMAP.md                  # 路线图
├── CHANGELOG.md                # 版本变化
└── .gitignore                  # 不应提交的本地文件
```

实际程序目录可能随版本调整，小说数据目录的兼容性应优先保证。

## 作品库

```text
小说项目/
├── projects.json
├── 作品/
├── templates/
└── .trash/
```

### `projects.json`

记录：

- 已创建小说
- 每本小说的项目 ID
- 显示名称
- 当前活动小说

Agent 在读写任何小说资料前，都应先确认活动项目。

### `作品/`

每本小说使用一个独立项目 ID 作为目录名：

```text
小说项目/作品/<project-id>/
```

项目 ID 用于保证目录安全，作者通常不需要手工修改。

### `templates/`

用于新建小说时复制通用骨架。模板不应包含某本真实小说的具体人物、设定或剧情。

### `.trash/`

网页中删除的小说或 Markdown 文件会先进入回收目录，而不是立即永久删除。

Agent 不应把 `.trash` 中的内容当成当前事实。

## 单本小说目录

```text
小说项目/作品/<project-id>/
├── 大纲/
├── 写作规范/
├── 正文/
├── 章节提交/
├── 审查报告/
├── 记忆库/
│   ├── current/
│   ├── index/
│   └── snapshots/
└── 档案库/
```

## 大纲

存放不同层级的规划：

```text
大纲/
├── 原始大纲.md
├── 总纲.md
├── 第01篇_*.md
├── 章节规划.md
└── 细纲_第001章.md
```

- 原始大纲：作者最初输入，可以很粗糙。
- 总纲：故事总体方向和核心冲突。
- 篇纲：一段完整故事阶段的目标与章节范围。
- 章节规划：全局章节安排。
- 章节细纲：写某一章前确认的具体任务。

篇纲名称不应被写死为“第一卷”。Agent 应根据文件元数据或章节范围选择对应篇纲。

## 写作规范

用于保存：

- 文风和题材方向
- 章节审查标准
- 反流水账要求
- 不同章节类型的写法参考
- 作者针对某本小说的特殊约束

规范应保留必要边界，但避免把创作限制成机械模板。

## 正文

正式保存的章节：

```text
正文/第001章_标题.md
```

正式正文是最高优先级事实来源之一。作者修改正文后，摘要和记忆应随之更新，而不是反过来覆盖作者的新版本。

## 章节提交

章节提交是结构化的创作记录，不是 Git commit。

它回答：

- 这一章发生了什么？
- 哪些状态改变了？
- 哪些关系和伏笔发生变化？
- 下一章必须承接什么？

它不应复制整章正文。

## 审查报告

保存章节质量与一致性检查结果，通常按 S1-S4 分类。

审查报告是建议和证据，不是新的小说事实源。

## 记忆库

### `current/`

只保存下一章仍可能生效的状态，例如：

- 角色当前位置与伤势
- 仍有效的关系变化
- 未完成任务
- 活跃伏笔
- 当前时间线
- 仍受限制的资源或规则

current 不是完整历史，不应无限追加。

### `index/`

保存便于检索的结构化索引。

索引的特点：

- 可以删除
- 可以重建
- 不是唯一事实源
- 不应覆盖 Markdown 原文

### `snapshots/`

保存完整篇章结束后的阶段摘要。

snapshot 用来减少后续读取负担，不用来替代正式正文和档案。

## 档案库

保存完整历史，例如：

- 角色历史
- 关系变化历史
- 伏笔从新增到兑现的过程
- 地点与设定历史
- 已失效或被替换的事实

已经结束的内容应从 current 移入档案，而不是直接删除。

## 备份建议

重点备份：

```text
小说项目/
```

建议：

1. 在重大结构变更前复制整个 `小说项目/`。
2. 不要只备份索引文件。
3. 不要把含私密正文的备份提交到公共 GitHub。
4. 测试迁移时使用小说副本。
5. 定期验证备份是否能够恢复。

## 不应提交到 Git 的内容

- `.env` 与真实 API Key
- Codex、浏览器或第三方服务登录会话
- 运行日志
- 临时目录
- 数据库缓存
- 私密小说正文（除非作者明确希望公开）
- 测试生成的大量中间文件

具体忽略规则见仓库根目录 `.gitignore`。
