# 记忆补丁格式

把 memory_patch 保存为 JSON 文件，或放在 Markdown 的 `json` 代码块中。顶层格式固定为：

```json
{
  "schema_version": 2,
  "patch_id": "chapter-001-v1",
  "kind": "chapter_result",
  "chapter": 1,
  "chapter_revision": "正文文件的 64 位 SHA-256",
  "source_revisions": {
    "大纲/细纲_第001章.md": "64 位 SHA-256",
    "记忆库/current/本章写作任务书.md": "64 位 SHA-256",
    "正文/第001章_标题.md": "64 位 SHA-256",
    "审查报告/第001章_审查报告.md": "64 位 SHA-256",
    "章节提交/第001章_章节提交.md": "64 位 SHA-256"
  },
  "summary": "林序确认陷落已经发生，并第一次看到物资解释倾向。",
  "ending_state": "林序仍在五金店区域，职业未定，尚未找到脱离条件。",
  "operations": []
}
```

## upsert

新增事实或按稳定 ID 更新现有事实：

```json
{
  "action": "upsert",
  "record": {
    "id": "character-linxu-career",
    "category": "character",
    "status": "active",
    "importance": "critical",
    "valid_from": 1,
    "valid_to": null,
    "entities": ["林序"],
    "tags": ["职业"],
    "source_chapter": 1,
    "content": "林序的职业栏显示为【未定】，尚未形成正式职业。"
  }
}
```

`status` 只能是 `active`、`tentative`、`closed`、`outdated` 或 `contradicted`。`importance` 只能是 `critical`、`high`、`normal` 或 `low`。

## close 与 archive

```json
{"action": "close", "id": "plot-first-escape", "reason": "第006章完成脱离"}
```

```json
{"action": "archive", "id": "scene-old-location", "reason": "角色已经离开该地点"}
```

`close` 把状态改为 `closed`；`archive` 改为 `outdated`。两者都会记录结束章节、补丁 ID 和原因，并迁入档案。

## 约束

- `patch_id` 和记忆 `id` 只使用小写英文字母、数字、点、下划线和短横线。
- 同一个补丁内不得重复操作同一 ID。
- `summary` 和 `ending_state` 必须填写，但不要复制整章正文。
- 不确定信息使用 `tentative`，不要写成 active 铁事实。
- 先 dry-run；任何操作失败时不得部分更新 current。
- `kind` 只能是 `chapter_result`、`outline_baseline` 或 `migration`。只有 `chapter_result` 进入下一章上下文和完成度统计。
- `chapter_result` 必须绑定细纲、任务书、正文、审查和提交；审查与提交正文中都要写出完整 `chapter_revision`。
- 旧 schema v1 patch 只做向后读取，不重写。一个章节有多个未分类旧 patch 时必须由作者确认唯一正文结果。
