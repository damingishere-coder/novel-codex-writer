# 章节审查规范

审查报告用于判断一章是否可以进入最终保存、章节 commit 和 memory_patch。它不是改写正文的地方，而是指出问题、证据、影响和修法。

## 严重度

- S1：硬性失败。包括字数不在 2000-2500、章节号错误、正文缺失、严重违背 current 投影或大纲。
- S2：必须修改。包括工程词泄漏、人物状态明显错误、承接断裂、结尾没有期待、伏笔处理前后矛盾。
- S3：建议修改。包括 AI 腔、套路句、节奏拖沓、爽点不清、对话解释过多。
- S4：轻微润色。包括标点、重复词、局部表达不顺、单句过长。

## finding 格式

每条问题都按下面格式写：

```markdown
### S2-001 工程词泄漏

- 证据：正文中出现“本章伏笔如下”。
- 影响：读者会看到写作工程痕迹，破坏沉浸感。
- 修法：改成角色可感知的线索或场景细节，不直接说“伏笔”。
```

## 去 AI 味报告模式

- 只报告问题，不自动大段重写。
- 必须给出正文里的具体证据。
- 修法要说明方向，不要替作者改掉整段风格。
- 优先保护人物口吻、题材气质和已有文风。

## 审查顺序

1. 先查 S1：字数、章节号、正文是否完整。
2. 再查 S2：工程词、承接、人物状态、设定一致性。
3. 再查 S3：AI 腔、套路句、节奏和爽点。
4. 最后查 S4：标点、重复、局部润色。
