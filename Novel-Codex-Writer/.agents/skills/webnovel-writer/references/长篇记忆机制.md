# 长篇记忆机制

## 分层

- 正文：章节原文，是已经写出的剧情事实。
- 章节提交与 memory_patch：保存每章摘要、章末状态和事实变化。
- current：只保存仍会影响后文的当前投影。
- `memory_index.json`：保存条目位置、状态、有效章节、实体和标签；可随时重建。
- 档案库：保存关闭、过期或矛盾记录的完整历史。
- snapshots：只保存篇末摘要和明确的人工基线。

## 写章前

先按章节范围匹配篇纲，再从细纲和索引选择不超过 20 条相关记忆。默认同时使用最近两章的结构化摘要、上一章章末状态，以及目标章之前连续最多五章的正文全文；不足五章时读取已有全部前章。

把选择结果和必须全文读取的前置正文路径写入不超过约 1500 字的 `本章写作任务书.md`。1500 字预算只约束任务书，不截断列出的正文原文。选择单位必须是完整记忆、完整规则、完整段落或完整表格行；不得截断条目。关键规则超过预算时停止并报告来源 ID。

写正文前逐个读取任务书列出的前置正文文件，以磁盘上的最新内容为准。正文与旧摘要或 current 冲突时先报告冲突，以用户最新修改的正文为准，并修正相关记忆。

## 写章后

生成结构化 memory_patch，再由 `update_memory.py` 合并 current、归档旧状态、记录章节摘要并重建索引。不要把章节摘要全文追加到 current。

## 增长控制

- 存储历史可以增长；任务书保持固定预算，另固定读取不超过五章近期正文。
- 已关闭信息移入档案，仍可按 ID 回查。
- 只在篇末生成 snapshot，不按固定五章周期重复压缩。
- 只有精确名称和标签检索无法满足真实召回测试时，才评估向量检索；默认不引入外部服务。
